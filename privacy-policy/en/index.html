MyMoney Privacy Policy

Last updated: August 16, 2026 · Русская версия

This Privacy Policy explains how MyMoney handles information in the Android application. MyMoney is a local-first money tracker developed by Kirill Shavrin.

Developer and contact

Developer: Kirill Shavrin

Information stored on your device

MyMoney stores its main data locally in the app's private storage. This can include accounts, currencies, exchange rates, categories, transactions, notes, budgets, recurring templates, goals, search history, synchronization journal and synchronization logs.

The app also stores settings such as language, theme, chart and display preferences, onboarding state, selected account and period, automatic-sync preference, timestamps, and a randomly generated installation/device identifier used to distinguish journal files during synchronization.

When you use the app lock, MyMoney stores a PIN hash and lockout state. When you connect an optional cloud provider, it stores the Dropbox refresh credential or Google Drive account email locally. Shared-workspace session fields, including account identifiers, email, access and refresh tokens, are stored in the encrypted secure store if that feature is enabled in a compatible build.

How the app uses information

MyMoney uses this information to display and calculate your finances, save your preferences, provide local backups and imports, run recurring and maintenance jobs, and perform synchronization only when the relevant feature is available and you choose to use it.

Information sent over the network

Exchange-rate service

When you request an exchange-rate refresh, the app requests the latest EUR-based rates from open.er-api.com. The request contains no transaction, account, category, note or other financial record from MyMoney. Returned rates are saved locally.

Optional Dropbox and Google Drive synchronization

Dropbox and Google Drive synchronization is available in the release build as an opt-in feature. The release artifact includes both providers, but no cloud data is sent until you connect the corresponding account and use synchronization.

If you enable and use one of these providers, MyMoney uploads and downloads append-only journal files containing the records needed to synchronize your data, which may include transaction amounts and dates, notes, account and category names, currencies, budgets or other supported entities, timestamps, record identifiers and the locally generated device identifier. Dropbox uses its app folder; Google Drive uses the private appDataFolder area. MyMoney does not add end-to-end encryption to these journal files; the provider's account controls and transport security apply.

Disconnecting a provider removes its local credential and synchronization binding, but does not delete an already uploaded remote journal. Remote copies still require provider-side deletion; delete remote files from the corresponding provider account if you want them removed.

Supabase Auth and Google OAuth

Compatible builds may include an optional Shared workspace feature. When that feature is enabled, users can sign in with Google OAuth through Supabase Auth. The sign-in flow uses the openid, email and profile scopes; this Google sign-in does not request Google Drive access. Supabase receives the Google identity token and maintains the authentication user, session and account data under its own policies.

Shared workspace data may include a user identifier, email address, workspace membership, workspace invites, operations and conflict records. The release build includes Shared workspaces as an optional feature and uses Google OAuth through Supabase Auth. The authenticated in-app account-deletion path is available after the production backend migration was deployed. It is safely blocked while the user has an active Shared workspace with other members; resolve that membership first by leaving the workspace or, as sole owner, deleting the workspace.

Error reporting with Sentry

Sentry is used only when a release build is supplied a non-empty Sentry DSN. In that case, MyMoney may send error events, stack traces and technical app/device/runtime context needed to diagnose failures. Tracing, performance monitoring, profiling, automatic session tracking, screenshots, view-hierarchy attachments and Session Replay are disabled in the app configuration. Sentry's own privacy policy and retention rules also apply.

Services and feature flags

Firebase Remote Config is not enabled in this release. Dropbox, Google Drive and Supabase are included in the release artifact, but they transmit data only after you connect and use the corresponding feature.

Advertising (Google AdMob)

MyMoney shows rewarded ads only — an ad never appears unless you deliberately start one to earn temporary Plus access. There are no banner, interstitial or app-open ads. When you start a rewarded ad, the Google Mobile Ads SDK collects your device's advertising ID (com.google.android.gms.permission.AD_ID) and technical device and request context, and may use them to select and measure the ad. Google's own advertising policies apply. The reward itself is confirmed to MyMoney's backend by Google through server-side verification; the confirmation carries an opaque identifier tied to your account, not your financial records. No transaction, account, category, note or other financial record from MyMoney is ever sent to Google's advertising services. Ads are not served in every region; where they are unavailable, the rest of the app is unaffected.

Backups and exports

You can export a database backup or CSV through Android's file picker. Such files may contain your financial data and are written to the location you select. MyMoney does not upload these files by itself. The app's secure credentials and PIN hash are excluded from Android system backup; Android device-to-device transfer may include the local database and ordinary settings according to the device's backup rules.

Retention and deletion

Local data remains on the device until you delete it in the app, use the available reset controls, clear the app's storage, or uninstall the app, subject to Android and device-backup behavior. Provider copies and Sentry error events are controlled by the relevant provider's account and retention policies. Authenticated users can request account deletion from the release app after resolving any active Shared workspace conflict. If the app is inaccessible, use the public MyMoney account and data deletion page or the email request process. Remote Dropbox and Google Drive copies still require provider-side deletion directly in the provider account.

Security

Room database data and ordinary preferences are stored locally in the app sandbox. Provider credentials, PIN data and shared-session tokens are stored with Android encrypted preferences backed by an Android Keystore master key. No security measure can guarantee absolute security, so keep exported backups and connected provider accounts protected.

Changes to this Policy

This Policy may be updated when MyMoney's data practices or enabled services change. The date at the top indicates the latest revision.
