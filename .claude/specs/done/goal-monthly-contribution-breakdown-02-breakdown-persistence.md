## Acceptance (UI-agnostic)
```gherkin
Feature: Persist the contribution breakdown with a goal

  Scenario: Round-trip a goal with a breakdown
    Given a goal whose advanced breakdown is enabled with incomes and expenses
    When the goal is saved and then loaded again
    Then the breakdown is restored with the same rows, names, and exact amounts

  Scenario: Goal without a breakdown
    Given a goal with no advanced breakdown
    When the goal is saved and loaded
    Then it loads with a disabled, empty breakdown

  Scenario: Existing goal survives the upgrade
    Given a goal stored under database version 2
    When the database migrates to version 3
    Then the goal still loads and its breakdown is disabled and empty
```

## Gap / context
SPEC-01 added `Goal.contributionBreakdown` in the domain but nothing persists it — a reopened goal would
lose the rows, breaking D1/D5. This SPEC carries the value across the storage boundary with the minimal
schema change (one nullable TEXT column + a forward migration) and the mandatory instrumented migration
test, so the breakdown survives app restarts and DB upgrades.
